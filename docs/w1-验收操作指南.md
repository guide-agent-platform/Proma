# W1 验收操作指南（B 端到端 + C3 清告警）

> 用途：手把手完成 M1 最后两项——B 手工端到端验证（硬指标）+ C3 清启动告警。
> 对象：在桌面操作的人。代码侧已全绿（typecheck 4 包通过、bun test 5/5），只剩这两步需要 GUI。
> 预计耗时：20-30 分钟（含录屏）。

---

## 0. 前置准备（2 分钟）

1. **暂停 OneDrive 同步**：任务栏 OneDrive 图标 → 设置 → 暂停同步 2 小时。
   （dev 模式会编译产生文件，避免 OneDrive 占用文件导致报错。）
2. 确认 bun 可用：打开终端（Git Bash 或 PowerShell）
   ```bash
   bun --version    # 应输出 1.3.x
   ```
3. 确认 workspace 已建（应能看到 guide-elasticity）：
   ```bash
   ls ~/.proma-dev/agent-workspaces/guide-elasticity/skills/guide-elasticity/SKILL.md
   ```
   - 如果**文件不存在**，先补建：
     ```bash
     cd "C:/Users/17359/OneDrive/Desktop/Proma-main"
     node scripts/create-workspace.ts
     ```
     然后确认 `~/.proma-dev/agent-workspaces/guide-elasticity/skills/guide-elasticity/SKILL.md` 存在（这个 SKILL.md 是手写交付物，脚本不会生成它，若丢失需从交接产物复制回去）。

```bash
cd "C:/Users/17359/OneDrive/Desktop/Proma-main"
bun run dev:electron
```

- 等待编译，几十秒后**桌面会弹出 Proma 窗口**。

## 3. B：手工端到端验证（核心，硬指标）

### 3.1 新建 session 并选 workspace
1. 在 Proma 窗口里点「新建 session」（或对应按钮）。
2. **workspace 选「向导弹性」（guide-elasticity）**——这一步最关键，选错了 Skill 不生效。
3. channel 任选一个可用的。

### 3.2 第一条消息：测「问 1-3 个问题」
输入并发送：
```
帮我做一个 hello world 页面
```
**观察点**：
- ✅ 期望：Agent 没有直接动手，而是**问 1-3 个关键问题**（比如给谁用、要不要样式等），最好以可点选项形式出现。
- ❌ 异常：Agent 一个问题不问、直接开始写代码 → Skill 可能没加载（见第 5 节排查）。

### 3.3 第二条消息：测「写 PRD」
直接给一个明确需求：
```
做一个记账应用，支持收入/支出记录和按月统计
```
**观察点**：
- ✅ 期望：Agent 判断需求已清晰，**调用 Write 工具**把 PRD 写到 `01_PRD/prd.md`，最后说一句"需求分析完成"。
- 验证文件真的写出来了：
  ```bash
  find ~/.proma-dev/agent-workspaces/guide-elasticity -name prd.md
  ```
  （路径会在某个 session 子目录下的 `01_PRD/prd.md`。）

### 3.4 录屏（2-3 分钟）
- 工具：Windows 自带 `Win + G`（Xbox Game Bar）录屏，或 OBS。
- 录制内容：启动窗口 → 新建 session 选 workspace → 发两条消息 → Agent 响应全过程。
- **录屏里不要露出 LLM API key**（别在录制时打开设置页的密钥栏）。
- 讲解用普通话，方便周六组会演示。
- 保存到：`docs/w1-recordings/frontend-demo-20260605.mp4`（目录没有就新建）。

## 4. C3：清启动红色 error

1. 回到 DevTools 的 **Console** 标签。
2. 找**红色 error**（黄色 warning 不用管）。
3. 对每条红色 error：记下报错信息和来源文件。
   - 如果是我们 W1 改动相关（agent-workspace / ipc / preload / writeToWorkspace）→ 截图发我，我来修。
   - 如果是 Proma 上游本来就有的 error → 记录即可，不在 W1 范围，别动。
4. 验收标准：启动后控制台**无新增的红色 error**（W1 改动没引入新错误）即可。

---

## 5. 出问题怎么排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| session 列表里没有「向导弹性」workspace | 没用 dev:electron 启动 / workspace 没建在 .proma-dev | 确认用 `bun run dev:electron`；跑第 0 节的 create-workspace 脚本 |
| Agent 不问问题、直接写代码 | Skill 没被加载 | 确认 SKILL.md 在 `~/.proma-dev/agent-workspaces/guide-elasticity/skills/guide-elasticity/`；确认 `.claude-plugin/plugin.json` 存在 |
| Agent 完全没反应 / 报 API 错误 | LLM API key 没配 / 失效 | 在 Proma 设置里检查 key |
| 想确认 Skill 进了 system prompt | —— | DevTools Console 里搜 "向导弹性" 或 "guide-elasticity" 看 prompt 日志 |
